# Start development

Explicitly assigned specialists follow their task and role instructions.

When the project exposes `loop-native` tools, use the `loop-engineering` skill:
inspect actual progress, reconnect/begin a native team, prepare stage requests,
ask questions in this conversation, and apply task proposals through Loop.
Show stages, assigned roles, real checks and blockers, and open the local
dashboard when the host supports it. The current host owns dialogue and native
delegation; do not start a nested `team-run` for ordinary native-host work.
Retain existing team ownership, accepted scope and accounting limitations.

As coordinator, read existing repository instructions, `LOOP.md`, your role,
workflow, execution, spec, questions, team, plan and handoff under `.loop/`.
Review requirements, then select from `scenario.json` using activation rules
and record decisions in `team.json`. Read every active or covered role contract.
Read the shared protocol declared by the roster and each role's professional
procedure; retain separate results for duties covered by another active owner.

When requirements are absent, begin with `.loop/setup.md`: the requirements
agent reads existing docs, collects actual answers and prepares `.loop/spec.md`.
The user may supply an idea, documents or an existing spec. Own task/check setup,
assignments, integration, verification and delivery. Ask for requirements only
if absent; avoid repeating answered questions.

Use actual authorized host tools. Record delegated/sequential execution and
pending independent reviews; role files launch no agents. In controller
proposal-only mode, follow its ContextBundle and return one AgentStep.
